# GateShift 서비스 기획

## 타겟과 문제

첫 타겟은 인천공항 T1에서 출국심사를 마치고 탑승 전 식사나 수유실 이용을 계획한 가족 여행객이다. 항공편 상태 변경을 알아도 현재 위치, 새 탑승구, 시설 이용에 필요한 시간, 도착지 호텔 마감 조건을 따로 확인해야 한다.

GateShift는 항공편 변경을 계기로 사용자가 저장한 할 일과 예약을 확인하고, 달라진 판단과 다음 행동을 제시한다.

## MVP

| 요구사항 | 사용자 흐름과 완료 기준 |
| --- | --- |
| GS-01 여행 관리 | 편명과 출발일로 여행을 등록·조회·수정·삭제한다. 공개 데모는 브라우저 세션별로 편집 데이터를 분리한다. |
| GS-02 공항 할 일 | 가까운 게이트나 공항 구역을 현재 위치로 선택한다. 수유실과 식사를 저장하고 이동·시설 이용·탑승 여유를 반영한 계획 및 제외 이유를 본다. |
| GS-03 호텔 예약 | 호텔 1건과 안내문을 등록한다. 마감 시각, 예외, 연락 방법의 후보와 원문을 보고 확인하거나 수정한다. 도착 예정 시각과 이동시간을 기준으로 마감 확인이 필요한지 본다. |
| GS-04 변경 대응 | 게이트, 탑승 기준 시각, 도착 예정 시각 등의 변경을 반영한다. 영향받은 카드와 변경 이유가 지도·타임라인에 표시된다. |
| GS-05 데이터와 데모 | 공항 운항 데이터를 조회한다. 별도의 시나리오 재생은 데모로 표시하고, 같은 입력으로 정상→변경→정정 흐름을 반복할 수 있다. |

공항 시설은 T1 출국심사 이후 일부 구역의 식사·수유 시설 8~12개를 목표로 한다. 실내 위치 자동 측정, 전 공항 길찾기, 환승, 호텔·항공권 자동 변경, 보험 보상 분석은 확장 후보다.

## 대표 시연

1. 가상 가족 여행을 열고 현재 위치, 수유실과 식사 계획, 호텔 체크인 카드를 확인한다.
2. 도착 예정 시각 지연과 탑승구 변경을 재생한다. 기존 탑승 기준을 사용하되 새 안내 확인이 필요함을 표시한다. 동선이 길어져 식사를 제외하고, 호텔 카드에는 예외 조건과 함께 늦은 체크인 문의를 보여준다.
3. 탑승 시각 정정만 재생한다. 공항 카드가 다시 계산되고 호텔 결과는 유지된다.
4. 변경 이력에서 입력 변경, 재평가 대상, 판단 이유를 확인한다.

시설 운영시간과 구역별 이동시간에는 출처 또는 추정 여부를 표시한다. 확인되지 않은 탑승 마감이나 호텔 조건은 확인 필요로 표시한다.
