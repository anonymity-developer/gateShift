# 협업 컨벤션

## 브랜치와 이슈

- `main`을 공용 기준 브랜치로 사용한다. 최초 초기화 이후에는 작업 브랜치에서 PR을 연다.
- 브랜치는 `<type>/<issue>-<short-description>` 형식을 사용한다. 예시는 `feat/12-flight-watch`다. 이슈가 없는 작은 작업은 `docs/update-readme`처럼 적는다.
- 유형은 `feat`, `fix`, `docs`, `refactor`, `test`, `chore` 중에서 고른다.
- 이슈에는 목표, 완료 조건, 프론트·백엔드 간 합의가 필요한 점을 짧게 적는다.

## 커밋과 PR

- 커밋 및 PR 제목은 `type(scope): 변경 요약` 형식을 사용한다. 범위가 자명하면 `type: 변경 요약`으로 적는다.
- 스코프 예시는 `frontend`, `backend`, `flight`, `hotel`이다. 예시 커밋 메시지는 `feat(flight): 운항 변경 이벤트 기록`이다.
- PR에는 변경 요약, 검증 방법과 결과, API·DB 변경, 화면 변경 시 캡처를 남긴다. 연결된 이슈를 완료한 경우 `Closes #12`처럼 연결한다.
- 기능 PR은 팀원 한 명이 리뷰한다. API·스키마가 바뀌면 두 파트가 함께 확인한다. 병합은 squash merge를 기본으로 한다.
- 정렬·포맷 변경을 기능 작업과 섞지 않는다. 환경설정과 테스트에 사용하는 키는 예시 값만 커밋한다.
